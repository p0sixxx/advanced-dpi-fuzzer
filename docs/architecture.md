# Архитектура и алгоритмы

## Модули

## Пространство поиска

Факторы Native Desync и их применимость:

| Фактор | Значения (поиск) | Применим, если |
|---|---|---|
| `mode` | split, tlsrec, disorder, oob, fake, fake_split, fake_disorder, multi_split, multi_disorder | всегда |
| `split_pos` | 1,2,3,5, midsld, midsld±2, sni, sniext+1, host+1, endhost-1, extlen; 8 списков | режим ≠ fake; списки только для multi_* |
| `fooling` | '', md5, badsum, badseq, badack, timestamp, datanoack, autottl, md5_badack, badseq_badack_badsum, hopbyhop (только IPv6) | режим с фейками |
| `fake_ttl` | 2–12 | режим с фейками |
| `fake_sni` | авто, 16 доменов белого списка, rndsni | режим с фейками |
| `repeats` | 1,2,3,4,6,8,11 | режим с фейками |
| `split_delay_ms` | 0,1,2,5,10 | режим ≠ fake |
| `seqovl` | 0,1,2,4 (< первой позиции) | split/disorder/fake_split/fake_disorder/multi_* |
| `syndata`, `wsize`, `ipfrag`, `tlsrec_first` | вкл/выкл, 0–2 | всегда (tlsrec_first ≠ tlsrec) |
| `udp_*`, `udplen` | — | только при QUIC-целях |

Неприменимые факторы удаляются при канонизации, поэтому, например, `mode=disorder fake_ttl=4` и
`mode=disorder fake_ttl=8` — одна стратегия (в tachyon-core `Disorder` использует TTL=1 и не
читает `fake_ttl`).

## Выбор алгоритма поиска

Испытание дорогое (секунды, реальная сеть), шумное (бернуллиевский исход) и выполняется по
категориальному пространству с зависимыми факторами. Сравнение подходов:

| Подход | Плюсы | Минусы здесь | Решение |
|---|---|---|---|
| Полный перебор | полнота | 10⁶+ комбинаций | нет |
| Pairwise (покрывающие массивы) | все парные взаимодействия за десятки проб | без адаптации | **первичный скрининг** |
| Multi-armed bandit (Thompson) | оптимален при шуме, сам решает «новое vs перепроверка» | нужен априор для непроверенных | **ядро цикла** |
| Байесовская оптимизация (GP/TPE) | эффективна в непрерывных пространствах | категориальные + условные факторы, мало данных | заменена аддитивным логистическим суррогатом с шринкажем |
| Генетика / эволюция | находит комбинации | сотни особей → сотни проб | **мутации ±1 фактор вокруг лидеров (бим-поиск)** |
| RL | — | требует тысяч эпизодов | нет |

Итоговый цикл — sequential model-based optimisation:

1. Пул = seeds (пресеты tachyon-core, стратегии Tachyon, значения UI) ∪ прошлые победители ∪
   pairwise-план (~270 кандидатов для Native Desync).
2. На каждом шаге суррогат переобучается; для каждой стратегии и каждой обязательной цели
   берётся выборка из `Beta(1 + s·p₀ + k, 1 + s·(1−p₀) + n − k)`, где `p₀` — прогноз суррогата;
   значение стратегии = минимум по целям − λ·сложность. Тестируется максимум.
3. Непроверенные стратегии на скрининге — `stop_on_fail` (проба прекращается на первом отказе,
   пропущенные цели — отсутствие данных, а не неудачи).
4. Лидеры (бим шириной 4) порождают до 24 мутаций по полному домену всех факторов.
5. Стратегии с верхней границей ниже лучшей нижней границы исключаются.
6. После поиска — упрощение победителя (non-inferiority против исходного победителя, допуск 0.05).
7. Финал: до 3 устоявшихся + до 5 перспективных стратегий соревнуются **на свежих испытаниях**
   (исключает «проклятие победителя» — переоценку стратегии, выбранной по тем же данным), с
   исключением отстающих.

## Оценка

* Вердикт каждой пробы: `ok`, DPI-признаки (`tls_timeout`, `tls_reset`, `recv_reset`,
  `cutoff_16k`, `short_body`, `content_mismatch`, `tls_cert`, `server_rejected`, …) и
  не-DPI (`dns_fail`, `connect_failed`, `proxy_error`, `server_error`) — последние не считаются
  против стратегии.
* Baseline (direct-аутбаунд того же временного ядра): цели `open` / `blocked` / `partial` /
  `unreachable`. Недоступные без обхода по L4 исключаются.
* Полезность: `LB_worst − 0.05·штраф_латентности − 0.01·сложность` — надёжность доминирует,
  простота решает только при равной надёжности.

## Обучение

* Вес испытания `0.5^(возраст/14 дней) × 0.25^(эпох назад)`.
* Переоценка до 3 прошлых победителей в начале прогона (5 пакетов без stop_on_fail).
* Значимое падение доли успеха (односторонний z-тест, α≈0.01) → новая эпоха, старые данные
  резко теряют вес, поиск продолжается без доверия к ним.
* Отвергнутые бинарником стратегии запоминаются для версии ядра и больше не пробуются.

## Безопасность

Бюджет (пакеты, запросы, время), минимальный интервал между пакетами, контроль каждые 8 пакетов
и после подозрительных провалов, экспоненциальный back-off, аварийная остановка после 6 подряд
отказов контроля, проверка памяти роутера (агент отказывается работать при MemAvailable < 24 МБ),
блокировка от параллельного запуска агента, `trap` с очисткой временного ядра.
